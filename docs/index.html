01 / ARCHITECTURAL RIGOR

Separation of concerns between memory safety and causal reasoning.

Most autonomous systems fail on production Linux because they run unbounded Python processes directly in the critical path. When memory starves, the reasoning engine itself is killed by the kernel. Tsuki physically isolates the enforcement plane from the diagnostic daemon.

01 /

The Memory-Pinned Guard Plane

PLANE A: RUST + eBPF CO-RE

Compiled to native machine code and pinned in physical RAM using mlockall(MCL_CURRENT | MCL_FUTURE). The guard plane maintains a strictly capped RSS memory budget (<42MB) and will never trigger an anonymous swap-out.

Kernel hooks attach directly via eBPF ring buffers to track Pressure Stall Information (PSI) at sub-millisecond granularity without synthetic scheduler jitter.

02 /

The Sandboxed Reasoning Daemon

PLANE B: ONNX INT8 + PYTHON 3.11

When PSI thresholds breach safety limits, Plane A signals Plane B over a local Unix domain socket. Plane B inspects process hierarchy metadata, cgroup lineage, and memory growth velocity using a quantized local model.

Plane B is treated as untrusted: it holds no root privileges, possesses zero network sockets, and cannot issue system commands directly. It outputs strictly typed JSON remediation intents.

03 /

Ephemeral Kernel Leases

INVARIANT: 100% REVERSIBLE MITIGATION

Every actuator adjustment (such as adjusting memory.high or dropping cpu.weight) is registered with an ephemeral time-to-live lease (300 seconds default).

If the system stabilizes or if the Tsuki daemon terminates unexpectedly, all cgroup limits immediately restore to their original state. Work is never terminated prematurely.
